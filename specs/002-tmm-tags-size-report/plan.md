# Implementation Plan: TMM Tags, Size & Report

**Branch**: `002-tmm-tags-size-report` | **Date**: 2026-05-08 | **Spec**: [spec.md](./spec.md)
**Input**: [specs/002-tmm-tags-size-report/spec.md](./spec.md) + [ux-spec.md](./ux-spec.md)

## Summary

This plan covers two layers of change to the standalone TMM tool (`public/tools/tmm/index.html`):

**Layer A — UX fixes** (breaking changes to 001-tmm UI): Replace the modal-per-initiative add flow with an Inbox bulk-add panel; move the detail panel to always-open edit mode with dirty-flag close gating; replace the Category field with Tags + Size.

**Layer B — New features** (002-tmm scope): Tags with `#token` validation and single-tag canvas filter; T-shirt sizing with size-proportional dot diameters (XS=16px → XL=58px) and hollow dot for null size; spreadsheet-editor Report view (inline cell editing for Name/Tags/Size/Details; Q read-only) with bulk tag assignment and markdown export; unsaved-changes red banner.

**Technical approach**: All changes are HTML/CSS/JS edits to a single standalone file. No build tools, no new dependencies, no framework. Manual testing is primary (Constitution VII standalone exception).

## Technical Context

**Language/Version**: HTML5 + ES5 JavaScript (no transpilation) + CSS3
**Primary Dependencies**: None — standard browser APIs only (Pointer Events, FileReader, Blob, URL.createObjectURL)
**Storage**: Browser memory (in-page `var` state) + user-controlled JSON file download/upload
**Testing**: Manual testing (Constitution VII standalone HTML exception); no automated test suite required
**Target Platform**: Desktop and laptop browsers (modern evergreen: Chrome, Edge, Firefox, Safari); no mobile/touch layout required (FR-UX-019)
**Project Type**: Single standalone HTML file
**Performance Goals**: All operations are local and instant; no performance budget needed
**Constraints**: Offline-first (Constitution I); no external requests; single file delivery; no build step
**Scale/Scope**: Single user, single session, up to ~50 initiatives (coaching session context)

### Phase A — UX Fixes (Layer A: breaking changes to 001-tmm UI)

These tasks modify existing 001-tmm UI elements. They MUST be completed before Layer B features are built, as Layer B adds to the new UI structure.

#### A1 — Toolbar & Layout Restructure

**Scope**: Modify the toolbar HTML to match the UX spec wireframe. Replace `[+ Add Initiative]` with `[+ Quick Add]`. Add `[📊 Report]` button. Add the tag filter dropdown. No functional logic yet — structural scaffolding only.

**UX spec refs**: Screen 1 — Canvas View toolbar layout
**FR coverage**: FR-UX-013 (banner placeholder), FR-UX-001 (empty state hint)

**Design decisions**:
- The Inbox panel is injected into the `#canvas-wrapper` as a left sidebar (`<aside id="inbox-panel">`)
- The detail panel moves from `position: fixed` to a right-side slot within `#canvas-wrapper` (flex layout)
- The unsaved-changes banner is inserted between the toolbar and `#canvas-wrapper`
- `#canvas-wrapper` flex layout: `[inbox] [canvas-area] [detail-panel]`

#### A2 — Inbox Panel (bulk add mode + list mode + collapse)

**Scope**: Implement the full Inbox panel lifecycle per Screen 1a wireframe.

**Sub-tasks**:
- A2.1 Inbox HTML structure: header, list area, entry form (Name, Tags, Size fields), collapse toggle
- A2.2 Quick Add button opens Inbox + activates bulk add mode
- A2.3 Entry form: Tab navigates Name→Tags→Size; Enter submits row and opens blank row
- A2.4 Inbox list: each row shows name + `[×]` delete; drag handle `⠿` for drag-to-canvas
- A2.5 Done button exits bulk add mode → list mode; `[─]` collapse; `[▶ N]` expand
- A2.6 `submitModal()` replaced: new initiatives go to `inboxItems[]` + `initiatives[]` with `x=null, y=null` (unpositioned); canvas dot NOT rendered until positioned

**UX spec refs**: Screen 1a — Inbox Panel
**FR coverage**: FR-UX-001, FR-UX-002, FR-UX-003, FR-UX-004, FR-UX-005, FR-UX-006

**Design decisions**:
- Unpositioned initiatives: stored in `initiatives[]` with `tmm.x = null, tmm.y = null`; also held in `inboxItems[]` as parallel list for rendering. `renderCanvas()` skips initiatives with `x === null`.
- Tags validation in Inbox form: same `validateTags()` helper; inline error shown below Tags input
- Size in Inbox form: `<select>` with XS/S/M/L/XL/blank options

#### A3 — Inbox Drag-to-Canvas

**Scope**: Implement drag from Inbox list rows onto the canvas.

**Sub-tasks**:
- A3.1 `pointerdown` on drag handle `⠿` creates ghost `<div>` (semi-transparent clone)
- A3.2 `pointermove` moves ghost with pointer; `pointer-events: none` on ghost
- A3.3 `pointerup`: hit-test canvas bounding rect; if inside → compute normalised (x,y), update `initiatives[i].tmm`, remove from `inboxItems[]`, call `renderCanvas()` + `renderInbox()`; if outside canvas → cancel drag, ghost removed
- A3.4 Inbox count badge decrements on successful drop

**UX spec refs**: Screen 1a interaction — Inbox drag-to-canvas
**FR coverage**: FR-UX-020, FR-UX-006 (badge update)

#### A4 — Detail Panel Redesign (edit-only, dirty-flag gating)

**Scope**: Refactor the detail panel to always open in edit mode with dirty-flag close gating. Remove Category field; add Tags and Size fields (placeholders — functional implementation in Layer B).

**Sub-tasks**:
- A4.1 Remove view-mode / edit-mode toggle; panel always opens in edit mode
- A4.2 Add `isDirtyPanel` flag + `editSnapshot`; set `isDirtyPanel = true` on first `input`/`change`
- A4.3 `[Close]` button: visible always; styled disabled (`opacity: 0.4; cursor: not-allowed; pointer-events: none`) when `isDirtyPanel`
- A4.4 Click same dot: closes panel if `!isDirtyPanel`; blocked if `isDirtyPanel`
- A4.5 Click blank canvas: does NOT close panel (remove existing close-on-canvas-click behaviour if present)
- A4.6 Replace Category `<input>` with Tags `<input>` + Size `<select>` in HTML; wire up to `confirmEdit()` (no validation yet — added in B1)
- A4.7 Add `[Delete]` button → confirmation dialog → delete initiative from `initiatives[]` + redraw

**UX spec refs**: Screen 2 — Detail Panel
**FR coverage**: FR-UX-007, FR-UX-008, FR-UX-009, FR-UX-010, FR-UX-011, FR-UX-012

**Design decisions**:
- Cursor placed in Name field on panel open (`document.getElementById('edit-name').focus()`)
- `[Close]` is `<button id="btn-panel-close">` — existing ID preserved; behaviour changes
- Delete dialog: inline `<div>` within the panel (not a separate modal), shown/hidden with CSS
- Tab order in panel: Name → Tags → Size → Details → Confirm → Name (FR-UX-007)

### Phase B — New Features (Layer B: 002-tmm-tags-size-report spec)

#### B1 — Tags Field with Validation and Canvas Filter

**Scope**: Implement Tags field in detail panel with `#token` validation; tag filter dropdown on canvas; filter indicator.

**Sub-tasks**:
- B1.1 `validateTags(input)` helper: trim, split on whitespace, test each token against `^#\S+$`; return `{ tokens, invalid, valid }`
- B1.2 Wire Tags validation into `confirmEdit()`: on invalid → show inline error; block save
- B1.3 Wire Tags validation into Inbox form submit (A2 integration)
- B1.4 Tag filter `<select>` in toolbar: populated from union of all `tags` in `initiatives[]` on every `renderCanvas()` call; includes `(all tags)` as default option
- B1.5 Filter state: `activeTag` var; on `<select>` change → set `activeTag`; `renderCanvas()` skips dots where `!initiative.tmm.tags.includes(activeTag)` when filter is active
- B1.6 Filter indicator: when `activeTag !== null`, show `[× Clear]` button next to the filter `<select>`; clicking it resets `activeTag = null` and re-renders
- B1.7 Empty canvas when filter matches no initiatives: show "No initiatives match this filter" centred hint; filter indicator still visible
- B1.8 Update `saveToFile()`: write `tags` array, omit `category`
- B1.9 Update `loadFromFile()`: read `tmm.tags` (default `[]`); ignore `tmm.category` (FR-US6.08)
- B1.10 Update `renderCanvas()` detail panel populate: read `tags` as array, render as space-separated string in Tags input

**UX spec refs**: Screen 1 — Tag filter; Screen 2 — Tags field
**FR coverage**: FR-UX-017, FR-US6.01–FR-US6.08, FR-UX-013 (isDirty on edit)

#### B2 — T-Shirt Sizing (dot visual + detail panel)

**Scope**: Size field in detail panel; size-proportional dot rendering; hollow dot for null size.

**Sub-tasks**:
- B2.1 Size `<select>` in detail panel: options XS/S/M/L/XL/blank; default blank (null)
- B2.2 `applyDotSize(dotEl, size)` helper: sets `width`/`height`; transparent fill + border for null; filled for sized (see quickstart.md for reference)
- B2.3 `renderCanvas()`: call `applyDotSize()` for each dot
- B2.4 `confirmEdit()`: write `size` to `initiatives[i].tmm.size`; trigger `renderCanvas()`
- B2.5 Update `saveToFile()`: write `size` field to `tmm` section
- B2.6 Update `loadFromFile()`: read `tmm.size`; validate against enum; default to `null` if invalid/absent
- B2.7 Inbox form Size `<select>`: same options; value written to initiative on Quick Add

**UX spec refs**: Screen 1 — dot fill; Screen 2 — Size field
**FR coverage**: FR-UX-018, FR-UX-021, FR-US7.01–FR-US7.06

#### B3 — Unsaved Changes Banner

**Scope**: Red banner shown when `isDirty = true`; hidden when `isDirty = false`.

**Sub-tasks**:
- B3.1 Add `<div id="unsaved-banner">` HTML between toolbar and canvas-wrapper; hidden by default
- B3.2 `setDirty(val)` helper: sets `isDirty`, shows/hides banner
- B3.3 Call `setDirty(true)` on: add initiative, drag to canvas, confirm edit, delete initiative, drag reposition
- B3.4 Call `setDirty(false)` on: save success, load success
- B3.5 Banner text: "Changes not saved — click 💾 Save to preserve your edits"
- B3.6 Banner also shown in Report view (B4 integration)

**UX spec refs**: Screen 1 — unsaved-changes banner; Screen 3 — same banner
**FR coverage**: FR-UX-013

#### B4 — Report View (spreadsheet editor + bulk tag + markdown export)

**Scope**: Full-screen Report view replacing canvas view; `<table>` with Q/Name/Tags/Size/Details columns; inline cell editing for Name/Tags/Size/Details (Q read-only); keyboard navigation; checkbox per row; bulk tag apply; Export Markdown download; Back to Canvas.

**Sub-tasks**:
- B4.1 HTML: `<section id="report-view">` with toolbar (`[Export Markdown]`, `[← Back to Canvas]`), unsaved banner slot, `<table id="report-table">`
- B4.2 `renderReportView()`: populate table from `initiatives[]`; derive Quadrant using `deriveQuadrant(x, y)`; Q column cells — no `tabindex`, no `aria-selected`, not reachable by keyboard; editable cells — `tabindex="0"`, `role="gridcell"`, `aria-selected` managed by focus
- B4.3 `currentView` toggle: `[📊 Report]` sets `currentView = 'report'`, hides canvas, shows report; `[← Back to Canvas]` reverses; canvas reflects all inline edits immediately on return (FR-US8.04e)
- B4.4 Checkbox per row: `<input type="checkbox">` in first column; select-all checkbox in header
- B4.5 Bulk tag: `<input id="bulk-tag-input">` + `<button id="btn-bulk-apply">Apply to selected`; validates single `#token` format; appends to `tags[]` of all checked rows; deduplicates; calls `setDirty(true)`; re-renders report table (FR-US8.05–FR-US8.09)
- B4.6 "No rows selected" inline message when bulk apply triggered with no checkboxes (FR-US8.08)
- B4.7 Empty report state: show "No initiatives yet — go back to the canvas to add your first initiative." when `initiatives.length === 0`
- B4.8 `exportMarkdown()`: build GFM table string (Contract 3 format); `Blob` + `URL.createObjectURL`; trigger download as `effectiveness-toolkit-tmm-report.md`; pipe characters in Details escaped as `\|`; null size = empty cell (FR-US8.10–FR-US8.11)
- B4.9 Keyboard navigation — single `keydown` listener on `#report-table`:
  - Arrow keys and Tab/Shift+Tab move focus between editable cells; Q column skipped (FR-US8.04a)
  - Enter on a focused cell activates edit mode: cell content replaced by `<input type="text">` (Name, Tags, Details) or `<select>` (Size); cell value pre-populated (FR-US8.04b)
  - Tab or Enter while in edit mode: attempt commit (see validation below), advance focus to next editable cell
  - Esc while in edit mode: discard changes, restore previous cell text, exit edit mode (FR-US8.04b)
  - Click on an editable cell: same as Enter (activate edit mode directly)
- B4.10 Cell commit logic:
  - **Name**: trim whitespace; reject empty (inline error: "Name is required"); on valid commit → update `initiatives[i].name`; ID unchanged (FR-US8.04d); `setDirty(true)`; re-render cell
  - **Tags**: call `validateTags()` helper; on invalid → block commit, show inline error below cell — "Use # prefix — e.g. #health" (FR-US8.04c, FR-UX-017); on valid → update `initiatives[i].tmm.tags`; `setDirty(true)`; re-render cell
  - **Size**: `<select>` with options XS/S/M/L/XL/blank; commit on Tab/Enter/blur; update `initiatives[i].tmm.size`; `setDirty(true)`; re-render cell
  - **Details**: multi-line `<textarea>`; Enter = new line; Tab = commit and advance; update `initiatives[i].tmm.details`; `setDirty(true)`; re-render cell
  - All commits immediately update `initiatives[]` — single source of truth (FR-US8.04e, FR-000.07)
- B4.11 Ensure canvas tag filter and `isDirty` state are preserved when switching views; `renderCanvas()` called on return to canvas so all inline edits (name, tags, size) are reflected immediately

**UX spec refs**: Screen 3 — Report View (FR-UX-014, FR-UX-015, FR-UX-016, FR-UX-017)
**FR coverage**: FR-UX-013, FR-UX-014 (keyboard nav + inline cell editing), FR-UX-015, FR-UX-016, FR-UX-017, FR-US8.01–FR-US8.11, FR-US8.04a–e, FR-000.07
